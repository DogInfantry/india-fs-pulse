## Visualisation and design tooling supplied for this project

Every one of these was evaluated. Recording the **rejections** matters as much as the
adoption: choosing a tool is only half a sourcing decision, and the JD asks explicitly
for the ability to "identify relevant tools and sources".

| Resource | Link | Verdict |
|---|---|---|
| **Perspective** | https://github.com/perspective-dev/perspective | **Rejected for this site.** Genuinely excellent for large or streaming datasets; ships multiple megabytes of WASM to pivot 36 rows. The workbench is ~40 lines of DOM code instead, which is why Lighthouse stays at 100 |
| **Apache Superset** | https://github.com/apache/superset | Rejected — needs a live Python backend and a database; incompatible with static, free hosting |
| **Panel (HoloViz)** | https://github.com/holoviz/panel | Rejected — same backend constraint. Pyodide export exists but would ship a Python runtime to draw a bar chart |
| **Vizro (McKinsey)** | https://github.com/mckinsey/vizro | Rejected — Dash/Flask server required. Worth revisiting if this ever gets a backend |
| **Redash** | https://github.com/getredash/redash | Rejected — a hosted BI service, not a component; wrong shape for a portfolio artefact |
| **glue** | https://github.com/glue-viz/glue | Rejected — desktop linked-view exploration, not web publishing |
| **21st.dev** | https://21st.dev | Referenced for UI component and layout craft |
| **impeccable.style** | https://impeccable.style | Referenced for finish and typographic restraint (the local `impeccable` skill covers the same ground) |
| **awesome-design** | https://github.com/gztchan/awesome-design | Referenced as a design-resource index |
| **gitdesign.md** | design-notes convention | Referenced; this file and `docs/stack-decisions.md` play that role here |
| **WebGPU** | https://www.w3.org/TR/webgpu/ | Rejected — no dataset here is within three orders of magnitude of needing GPU compute |

**What was adopted instead:** Astro 5 (static), Tailwind v4, ECharts (lazily imported,
so the entry script is ~2.6 kB), and five hand-written server-rendered SVG components —
`Marimekko`, `Waterfall`, `Slopegraph`, `SmallMultiples`, `SlopeLines` — which carry the
consulting chart vocabulary with zero client JavaScript.

## How to refresh the browser-only sources

`docs/REFRESH.md` has the full procedure. The short version: NPCI blocks scripted access,
so those two tables are read in a browser and transcribed into
`data-pipeline/data/manual/` with a per-row `source_url` and `accessed` date.

Three traps documented there, all of which caused real bugs:

1. NPCI renders only **10 rows per table with no pagination**.
2. Before ~2024 those ten rows are **alphabetical, not ranked** — so PhonePe is absent
   from December 2022, which is why the per-app series starts 2023-12.
3. A `#` in an app name is NPCI's **third-party-provider marker, not a comment** —
   parsing with pandas' `comment='#'` silently truncates every row to `NaN`.
